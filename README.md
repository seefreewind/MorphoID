# MorphoID reproducibility code and frozen workflows

This version 2.1.0 clean reproducibility package accompanies the MorphoID conditional identifiability manuscript. The repository source contains original code, frozen configurations, target/fold definitions, aggregate display inputs, audit metadata, environment records and regeneration instructions. Regional model-analysis inputs remain available in the historical v2.0.0 clean release asset. The public code repository is https://github.com/seefreewind/MorphoID. The v2.1.0 source archive is sufficient for the documented Figure 4, Figure 5 and Table 1 display-only route. Scientific results have not been rerun or altered.

## Reproduction flow

1. Obtain GEO GSE250346 source data from https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE250346 and retain the source terms and access receipts.
2. Obtain official Owkin Phikon-v2 and its processor from https://huggingface.co/owkin/phikon-v2/tree/2ae989a9c40cffaa27f0a6cb29cc94d1d6f9a5fd.
3. Accept the applicable Owkin licence directly with the provider.
4. Verify frozen revision 2ae989a9c40cffaa27f0a6cb29cc94d1d6f9a5fd and checkpoint SHA256 261ae680fa699b3b951597fd57aa19c02ef735805acb104b93af69b36d928569; verify processor/config hashes in docs/PHIKON_REGENERATION.md.
5. Map the historical raw-data paths to a separate writable study copy; reconstruct prerequisite matrices, crop audits and hash-baseline inputs. Regenerate embeddings locally using scripts/regenerate_phikon_embeddings.py with --model-dir, --revision and --accepted-provider-terms.
6. Run the frozen common-universe analysis and Phase1E–1J sequence documented in docs/PHIKON_REGENERATION.md. Preserve all donor folds, independent PF-only fits, negative R² and training-side residual cross-fitting.
7. Run the original figure and report scripts to regenerate tables and figures locally. The final finite-donor inference limitation remains part of the scientific conclusion.

A portable end-to-end reproduction has not been executed for this rights update. The adapter only handles the duplicated full_crop_in_bounds merge input in memory after equality validation; scientific extractor bytes, coordinates, row order and estimands remain unchanged. Raw H&E images, expression RDS objects and original access receipts must be obtained/reconstructed by the user.

## Version 2.1.0 display reproduction

All required files are committed in the repository source, so GitHub–Zenodo automatic release archiving includes them. Download the source archive of tag v2.1.0 or clone that tag, then run from its root:

```sh
python3 -m venv .venv-display
.venv-display/bin/python -m pip install -r environment/requirements-display-lock.txt
.venv-display/bin/python scripts/reproduce_frozen_displays.py --output reproduced
```

Outputs: Figure4_Increment_Residual.svg/.png, Figure5_Shortcut_Controls.svg/.png, Table1_frozen_numeric.tsv and JSON provenance/export receipts. No fitting, imputation, bootstrap or new statistics occur. Table 1 contains the frozen numeric columns; narrative evidence labels remain in the manuscript. Existing confidence intervals and negative R² are preserved. SVG text remains editable. PNG resolution is 601 dpi at 183 mm width.

The script reuses the original figure 4–5 panels exactly, with portable input/output paths and SVG/PNG exports. Its six source tables are SHA256-verified before use. Historical environment records are retained and their stage limitations documented in environment/DISPLAY_ENVIRONMENT.md. The separate display environment does not establish end-to-end model reproduction.
